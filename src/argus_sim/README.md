# argus_sim — Gazebo worlds & drone model (Pillar 1)

Simulation assets for the GNSS-denied indoor environments, resolved at runtime
through the package's `GZ_SIM_RESOURCE_PATH` install hook. Simulator: **Gazebo
Harmonic (gz-sim 8)**, **dartsim** physics at 250 Hz (`max_step_size = 0.004 s`),
ogre2 render engine. Conventions: **ENU** world frame, **FLU** body frame, SI
units (full frozen spec: `docs/CONTRACT.md`).

## Assets

| Asset | Description |
|-------|-------------|
| `worlds/warehouse_corridor.sdf` | Frozen Day-1 contract world: 30×5×3 m warehouse corridor, zones A/B/C, slalom obstacles, racking, Zone-B flicker light. Generated by `worlds/generate_world.py`. |
| `worlds/tunnel_circuit.sdf` | Scenario E world: 202.8 m closed-circuit stadium tunnel (2×70 m straights + r=10 m end-caps, 6×3.5 m cross-section) for the 200 m drift gate, **with eight navigable in-lane obstacles**. Generated by `worlds/generate_tunnel_circuit.py`. |
| `worlds/detail.png` | PBR checker+speckle albedo texture — the deliberate feature-richness layer for the VIO front-end. Referenced relative to the world file. |
| `models/argus_drone/model.sdf` | Kinematic, gravity-disabled quadrotor carrying the full sensor suite + `VelocityControl` + `PosePublisher`. |

## Drone sensor suite (`models/argus_drone/model.sdf`)

Every sensor is an ogre2-rendered Gazebo sensor stamped on the sim clock and
bridged 1:1 to ROS by `argus_bringup`. Complete per-sensor working is in root
README §3.5; summary:

| Sensor | Mount (body FLU) | Spec | gz → ROS topic(s) |
|--------|------------------|------|-------------------|
| `cam0` (left, reference) | (+0.10, +0.06, 0) | 1280×720, R8G8B8, 90° HFOV, **15 Hz**, fx=fy=640, cx=640, cy=360, zero distortion | `/argus/cam0/image_raw`, `/argus/cam0/camera_info` |
| `cam1` (right) | (+0.10, −0.06, 0) | identical optics; **0.12 m baseline** to cam0 | `/argus/cam1/image_raw`, `/argus/cam1/camera_info` (P[3] patched to −76.8) |
| `imu` | (0, 0, 0) ≡ `base_link` | 6-DOF accel + gyro, **250 Hz**; at rest `a_z=+9.8` | `/argus/imu` |
| `lidar3d` (`gpu_lidar`) | short mast | 360 az × 16 el rays, ≤ 15 m, **10 Hz** | `/argus/lidar/points` (PointCloud2), `/argus/lidar/scan` (LaserScan) |
| `rangefinder` (`gpu_lidar`) | down-pointing | single beam, 0.10–20 m, **20 Hz** | `/argus/rangefinder` (LaserScan) |
| `PosePublisher` | — | ground-truth model pose, **100 Hz**, topic-only (no `world→base_link` TF) | `/argus/ground_truth/pose` |

**Actuation:** per-link `<gravity>false</gravity>` + a model `VelocityControl`
plugin make the drone holonomic and kinematic — it consumes `/argus/cmd_vel`
(body FLU: x fwd / y left / z up + yaw) directly and never falls. Heading and
lateral position are decoupled, which the tunnel `circuit_avoider` relies on.

## Tunnel in-lane obstacles

`generate_tunnel_circuit.py` seeds **eight collidable obstacles on the straights
only** (never the yawing arcs) and clear of the first ~14 m VINS init window:
amber crates, a red barrel, hazard-yellow partial blockages, a blue box, a green
crate, and one narrow-passage gap (~2 m centre clearance). Collision is **on** so
the autonomous nav must genuinely steer around them; saturated colours read
clearly to a judge and track well with KLT/stereo; model prefix `obs_` lets the
viz layer pick them out. Regenerate the bare gate tunnel with:

```bash
python3 worlds/generate_tunnel_circuit.py --clean   # no demo obstacles
```

## Building & launching

The worlds are **generated** — edit the `generate_*.py` script, re-run it, then
rebuild this package (`colcon build --packages-select argus_sim`); never edit the
`.sdf` by hand.

```bash
ros2 launch argus_bringup argus_sim.launch.py headless:=true                       # corridor
ros2 launch argus_bringup argus_sim.launch.py headless:=true world:=tunnel_circuit # 200 m tunnel
```

The full sensor/topic/frame specification is the frozen contract in `docs/CONTRACT.md`.
